# StringBuilder와 StringBuffer

String과, StringBuilder & StringBuffer의 차이에 대해 알아본다.

## 공통점

- Java에서 `String` 클래스는 불변이기 때문에, 문자열을 변경할 때마다 새로운 String 객체가 생성되어 메모리 낭비 + 성능 저하 발생
- `StringBuilder` 와 `StringBuffer` 는 가변 객체이므로 동일한 객체 내에서 문자열을 변경 가능

## StringBuffer

- 동기화 지원
- 모든 메서드가 `synchronized` 키워드로 동기화되어있음
  ⇒ 동기화 오버로드 때문에 `StringBuilder` 보다는 느림
- 멀티스레드 환경에서 여러 스레드가 동시에 문자열을 조작해야할 때 사용

## StringBuilder

- 동기화 미지원
- 빠름

## 어떻게 String보다 빠를 수 있는걸까

**1) 내부 버퍼를 사용한다.**

- 내부에 `char[]` 형태의, 실제 문자열 길이보다 여유 있는 크기의 버퍼를 사용함
- 문자열 추가/변경 시 `char[]`를 직접 조작함

**2) 메모리 재할당 & 데이터 복사 시 효율성**

- `String`은 새로 문자열을 변경할 때마다 새로 배열을 할당하고 이전 내용을 통째로 복사함(메모리 비용이 크다)
- `StringBuffer`, `StringBuilder`의 경우 기존 버퍼에 새로운 문자열을 이어붙인다

## 자바 기반 백엔드 사용 사례

1. 동적 SQL 쿼리 생성
2. 로그 메세지 생성
3. JSON/XML 응답 문자열 구축
4. 파일 경로 또는 URL 조합
5. 템플릿 엔진의 내부 동작
6. 데이터 파싱 및 포맷
